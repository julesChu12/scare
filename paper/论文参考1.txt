As a new technology developed in recent years, network security isolation devices are also rapidly evolving. They employ protocol isolation technology to achieve security domain isolation and information exchange between two different security domains.This paper aims to develop a GUI management system for isolation devices to perform operations such as security policy configuration, user management, and log querying. The main tasks are as follows:(1)Provide a GUI for lateral isolation devices to enable visual management: In power systems or other secure local area networks, on-site operation and maintenance personnel need to manage numerous network devices. A visual management software is required to facilitate their configuration and operations.(2)Provide security policy configuration for isolation devices: Security policies (i.e., whitelists) are the core function of lateral isolation devices. Providing visual rule configuration capabilities to add, modify, delete, and search rules is the most critical feature for field technicians to configure devices.(3)Provide user management for isolation devices: According to the "separation of powers" requirement in GBT 20279-2015 [1], isolation devices need to separate user groups by privileges: administrative group, operational group, and auditing group. The system provides privilege-based group management and isolates functions in the management system according to user permissions, ensuring users can only access features corresponding to their group privileges.(4)Provide logging capabilities for isolation devices: Log auditing is a vital function for most network devices. Logs record the time and specific actions of user operations on devices, playing a crucial role in device security and monitoring. Log recording and retrieval are indispensable functions in the isolation device management system, enabling auditors to query device operations efficiently.(5)Provide security policy file importexport functionality: Since the management system communicates via networks, when field technicians encounter network interruptions during the transmission of large security policy configurations, they can first export policies locally. After network recovery, the policies can be imported and deployed to isolation devices, ensuring technicians' efforts are preserved.KEY WORDS  Network Isolation  SQLite  TCP  Linux  QT  base64 研究背景2021年前，国内网络安全经历了快速发展的阶段，安全的技术要素进一步的提升。目前，工业企业的边界已经突破了传统工业控制系统范畴，海量的设备、多样应用、复杂链路以及繁琐的数据交互，使其安全防护的对象与范围急剧扩张。在新时期，无论是电子政务还是工业互联网领域，我们国家都面临着越来越复杂的网络安全和信息安全环境，提升自主可控网络安全隔离产品系建设能力，是我们的责任。网络安全时代，保护的是网络空间，安全产品越来越丰富，从老三样（防火墙、防病毒、IDS）到WAF、漏扫、IPS、审计等等众多安全产品、安全模式也从单一产品模式演进为产品+服务模式。网络安全隔离设备用于网络间，或网内主机间的安全隔离，可在IP网上构建一个安全的虚拟专网。网络业务应用在保证安全的前提下，实现用户指定的互联互通的功能，提供一个安全的网络加密传输平台。此设备具备在网络物理隔离的前提下实现数据安全、快速传递的功能。该系统应具有良好的人机界面，易于配置，同时可以实时监控和查看日志信息。通过工业安全隔离装置在边界上的应用，可为企业和ICS网络用户采取各自独立的鉴别机制和凭证。能够标识并鉴别工业安全隔离装置边界范围内受保护的资产。实现控制网络与合作网络间最小访问的技术。最关键的信息通信能够在最安全和可信的层级进行。网络隔离设备如此重要，那么对它的控制系统也是必不可少的。根据相关国标文件的要求，网络隔离设备应能够具备一款针对用户访问或修改工业安全隔离装置的灵活的GUI管理系统软件。它能够鉴别访问工业安全隔离装置的用户的角色，确认其是否有相应的权限。还能够针对特定应用服务，设定特定的通信策略。并且应具备基本的审计功能。综上所述，本课题旨在研究一款专用于网闸设备的管理系统，在设计与开发成本能为用户所接受的前提下，达到较高的安全性。[8]1.2  研究现状随着计算机技术的快速发展，网络技术也日新月异，人们也越来越依赖利用网络来发布和获取信息、共享和处理数据。由于网络的开放性，网络攻击，信息泄露等安全问题也层出不穷。信息化也对我国社会、经济、政治和军事发展的影响也愈发深刻。工业网络安全隔离通常部署在工业控制网络的边界，保护着工业控制网络的资产，或者部署在生产管理层与过程监控层之间，保护的资产为过程监控层网络以及现场控制层网络。此外，工业控制网络安全隔离与信息交换系统本身及它内部的重要数据也是受保护的资产。工业控制网络安全隔离与信息交换系统一般以两个主机加专用的隔离部件组成，包括内部处理单元、外部处理单元和专用隔离部件组成。专用隔离部件既可以是经过安全强化的运行专用信息传输逻辑控制程序的主机也可以采用包含电子开关并且固化信息摆渡控制逻辑的专用隔离芯片构成的隔离交换板卡。工业控制网络安全隔离与信息交换系统中的内外部处理单元通过专用隔离部件相连，专用隔离部件是两个安全域之间唯一的可靠物理信道。该内部信道裁剪了TCPIP等公共网络协议栈，采用私有协议实现公共的隔离。专用隔离部件通常有两种实现的方式：一是采用互斥的分时切换电子开关，以实现内部物理信道的通断控制，以这种切换方式完成信息的摆渡，从而在两个安全域之间形成一个不存在物理连接的隔离区；二是采用私有协议以逻辑方式实现协议隔离和信息传输。然而如何确保资源数据库和内网、专网的安全，就需要一种速度更快、功能更好、性能更强的隔离设备，来数据文件交换过程中的管理和安全问题。1.3  系统实现的目的以及意义网络安全的最终保障，最好的办法往往是隔离，防止信息泄露和非法入侵实现本质安全。本文采用数据加密base64算法，结合国产飞凌主板研究开发适合流程行业的网络及数据安全的应用，探讨并且解决上述问题。1.低碳安全（Low-Carb Security）理论默认拒绝策略：所有网络服务的初始策略都应该是拒绝所有，只允许最小权限的服务，不允许默认后的漏洞。网络安全隔离设备正是采用白名单的安全措施，通过设定一个允许设备的策略表，只有在这个策略表的设备才能通过隔离设备传输，没有列入的设备则被拒绝访问。这种机制可以有效防止未经授权的设备接入网络中，从而提升整体的安全性。所以，让现场运维人员可以可视化的定义白名单安全策略是至关重要的，本系统也将实现此功能以配合运维人员对隔离设备进行策略配置。2. 安全本质的逆向思考管理员需清晰掌握网络流量内容，而并不是依赖黑盒化的高级检测工具，也就是日志的透明化，对于设备的操作进行记录是非常重要的，比如用户的登录，登出操作，以便于现场维护人员分析设备的使用情况，通过对操作日志的洞察，提供针对性的技术支持。拒绝了传统安全行业过度复杂化的倾向。3. 分层控制与纵深防御尽管主张简化，但其理论包含多层次控制：本系统使用原始套接字，对协议进行全面管控，它是一种底层网络编程技术，开发者可以直接操作原始数据包，旁路传统的网络协议栈，直接与网络接口进行交互，并且可以自定义解析协议头部来实现灵活的数据处理。4. 对传统防火墙的批判与超越	根据《计算机信息系统国际互联网保密管理规定》第二章第六条，国家保密局明确规定：涉及国家秘密的计算机信息系统不得直接或间接与国际互联网或其他公共信息网络连接，必须实行物理隔离。因此，我国政府部门普遍采用的方法是在内网涉密网络与专网涉密网络之间实施防火墙逻辑隔离，在内网涉密网络与外网非涉密网络之间实施物理隔离。所以网闸要与传统防火墙技术的区分，传统防火墙依赖规则过滤和状态检测，而网闸更强调物理隔离和协议的终止。5. 实践方法论在策略可执行性上，安全规则需要简单明确，避免用户因复杂策略而违规。第二章  需求分析2.1 先把用来设置网闸的电脑安装网络安全设备管理系统，最后用网线连上网闸内端管理网口，最后内网交换机用交叉线连上网闸内端口，外端端口连上客户的外网交换机。2.2  业务分析由于隔离设备为2+1形式，是由内网主板+中间的隔离双端口+外网主板构成，设备的主要功能是根据策略文件中的策略进行数据包的过滤，符合策略文件则可以将数据包通过内网和隔离双端口传递至外网，外网同样根据策略文件判断数据包是否可以通过双端口传递至内网。隔离双端口主要将数据从网络协议中剥离并自定义格式然后传递至内网端或外网端，内外网端两端的交互是非网络传输的，双端口的驱动程序根据策略文件对接收到的数据包进行过滤。现如今无论是电力还是工业行业，对网络的安全性都是十分重视的，在现场机房都会有大量的，各个种类的网络安全设备需要进行配置与搭建，这时有一个方便的，易操作的GUI就显得十分重要了。当运维人员通过客户端配置好策略并下传到服务端后，服务端将策略生成一个策略文件，并通知底层驱动，驱动就会读取策略文件中的策略，并将策略文件的策略取反后通过双端口传递至外网端，这样内网端和外网端均由一份含义相同但方向相反的策略，此时网闸就可以根据策略进行工作了，由于本系统并不包含驱动程序的研究，仅对内网端一侧进行了模仿，故生成策略文件后并不通知驱动程序，只在固定位置生成策略文件。2.3  功能需求分析根据国标文件规定，网闸操作权限需要三权分立，下传策略仅为操作员权限，故需要管理员管理操作员和审计员，故需要一个用户表和用户管理功能部署在内网，以管理不同权限的用户，而审计功能是审计员的权限功能，它需要对用户操作隔离设备的操作进行记录，并显示这些记录，所以需要一个日志表对用户的所有操作进行记录。所以挑选了整个系统中比较核心的五大功能，并为用户工具软件设计五个界面。分别为通讯参数设置界面，登录界面界面、用户管理界面、策略配置界面、审计日志界面。通讯参数设置由于网络隔离设备可能处在不同的局域网下工作，网络号以及主机号都是根据现场情况随时改变的，所以需要一种手段通过GUI改变网络隔离设备的ip地址。并且当用户与网络隔离设备进行通信前，也要保证GUI所在的计算机与网络隔离设备处在同一网段，故而读取网络隔离设备配置口当前的ip并根据情况修改网络隔离设备的ip是十分重要的功能。于是设计为打开软件后的第一个界面上就要显示本机ip与网络隔离设备的ip，并且能够更改网络隔离设备ip。用户登录用户登录是一个管理系统必要的功能，用户名与密码是最基本的认证信息，而网络隔离设备还需要区分用户角色，根据国标文件GBT20279-2015，用户角色属性应分为授权管理员，授权审计员，授权用户等。所以将按国标文件的三权分立定义，分出来了管理员，操作员和审计员三个用户角色，每个用户角色登录后按它们的职责不同分别显示不同的界面。用户管理该功能由管理员进行操作，根据国标文件GBT20279-2015，用户管理属性包括用户名，用户角色，用户口令等，所以它负责对其他用户角色进行增加用户，删除用户的功能。网络隔离策略配置策略配置是网络隔离器的最核心功能，根据国标文件GBT20279-2015中的基本的信息流控制功能，网络隔离产品的安全功能策略应该能够通过配置访问控制列表进行信息流控制，访问控制列表的元素包括:源ip地址，目的ip地址，源端口，目的端口，协议号。所以对这些策略的配置与管理是必须实现的功能。日志管理该功能由审计员进行操作。根据国标文件GBT20279-2015，网络隔离产品安全功能应能对可审计事件生成一个审计记录，包括事件发生的日期和时间，事件的类型，主体身份和成功或失败事件等信息。并且根据国标文件要求，在实现该功能时也定义了生成审计记录的动作，并且提供了查看审计日志的功能以供现场运维人员分析查看。[2]图2-2设备管理系统的数据流图2.4 策略配置并不使用数据库而是文件进行存储，因为策略需要被底层驱动程序读取并使用，而底层驱动程序读取的就是文件。另一方面也考虑到效率问题，由于策略需要频繁变动修改，如果使用数据库的SQL语句势必会在服务端执行大量的数据库操作，而且客户端和服务端需要频繁的发送和接收tcp包来传递这些信息，这些都会使得客户端与服务端性能下降。所以本系统采用一次从服务端读取全部策略，并在客户端采用红黑树进行统一管理全部策略，当全部策略配置结束并下传策略时，在一次从客户端全部传递到服务端并生成新的策略文件。[13]第三章 心跳线模块心跳线对于服务端来说是十分重要的，由于网络的复杂性，很多时候物理链路的故障无法传递给进程，比如当网线断了，而慢系统调用进入了阻塞，此时进程无法感知物理链路出现了故障，就会一直阻塞占用资源。心跳线的出现就可以代替这些慢系统调用去感知物理链路的变化并及时释放资源。心跳线任务就是用上述任务管理模块进行控制的，它使用原始套接字与客户端的心跳线线程进行通信，一旦与客户端建立了tcp连接就会启动。errcode sigatomict类型的，避免了程序编译优化后主线程可能无法读到信号处理函数更改后的变化。这个变量是一道双保险，当主线程收到信号后，若此时正阻塞在慢系统调用，那么信号会迫使该系统调用立即返回并置错误码为EINTR，此时只需要判断该变量是否置1就可判断链路是否已中断，若中断释放连接即可。若主线程没有阻塞，那么当主处理流程结束前也会读该变量，若置1同样可以释放连接，这就避免了遗漏该变量变化进而仍然阻塞于慢系统调用的情况。启动心跳任务后首先需要获得网口的索引，关键代码如图4-3所示。图4-3 策略管理功能服务端仅负责策略文件的读写，客户端则负责维护策略以及策略的导入导出。策略的导入以及从服务端读取设备策略这两种动作都是从外部读取全部策略并进行管理和显示到客户端窗体，而策略的导出和下传策略到服务端都是将策略写到外部(本地文件或网络)。一条策略的格式如下:-n 1 -p 0 -e 192.168.1.2 -i 192.168.1.6 -dp 6789 -sp 0-n代表策略的id号，-p则是策略的过滤协议，当策略为0时代表可以通过的是一个TCP数据包，为1时则是一个UDP数据包。-e代表外网侧接入的设备ip地址，-i代表内网侧接入的设备ip地址。-dp代表目的进程的端口号，-sp代表源进程的端口号，若端口号为0则代表任意端口均可通过。根据这些定义，上面的示例策略代表有一个id为1的策略，它允许内网设备ip为192.168.1.6并且任意端口号的进程(任意的TCP进程)向外网设备ip为192.168.1.2并且端口号为6789的进程发送TCP包。当用户通过操作员登录后，显示策略管理界面如下图所示：图4-33
