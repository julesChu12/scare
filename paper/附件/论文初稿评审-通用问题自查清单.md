# 论文初稿评审通用问题自查清单（基于 22 份评审意见）

> 适用范围：本科毕业论文初稿修改。  
> 目标：提炼“跨项目通用问题”（非具体业务功能缺陷），用于你逐条对照修稿。  
> 数据来源：`初稿评审清单-*.doc`（共 22 份）。

---

## 一、你给的典型错误（已纳入总清单）

来自 `初稿评审清单-刘允路.doc` 的典型问题：

1. 任务书是空白的，需补充。
2. 数据库逻辑设计中的实体关系模式，主键要用下划线标识。

这两条都属于高频共性问题：
- 第 1 条属于“任务书/完成度材料不完整”；
- 第 2 条属于“数据库设计表达不规范”。

---

## 二、共性错误原因（非项目错误）

下面是跨多数评审单反复出现的通用问题，按“错误原因 -> 表现 -> 修改动作”整理。

### 1) 格式规范执行不到位

**常见表现**
- 每章未另起一页。
- 页眉、页码、封面信息、章节编号不规范。
- 未严格按学校论文模板排版。

**修改动作**
- 按学校模板逐页核对：封面、目录、正文、参考文献、致谢、附录。
- 检查页眉页码连续性，章标题分页，层级编号（如 `2.2 -> 2.2.1`）。

**评审原话示例**
- “论文格式不规范，需根据模板修改。”
- “每章要新起一页。”
- “页眉不对，页码序号不对。”

### 2) 参考文献“有列表、无规范引用”

**常见表现**
- 参考文献数量不足（多份意见要求约 15 篇）。
- 正文没有右上角引用标注，或标注与文后列表不一致。
- 文献偏旧，近 3-5 年文献比例不足。

**修改动作**
- 先补齐数量，再做“正文标注 <-> 文末条目”一一对应检查。
- 补充近年文献，保留中英文文献组合。

**评审原话示例**
- “参考文献过少，要15条左右，且需要标注再正文中。”
- “正文中的引文部分需在右上角按序标注参考文献。”

### 3) 摘要与关键词质量不足

**常见表现**
- 摘要过短或空白。
- 摘要写成“系统介绍”，缺少论文核心内容（问题、方法、结果）。
- 关键词不聚焦，或中英文混杂不当。

**修改动作**
- 摘要按“背景/目标 -> 方法 -> 实现 -> 结果”重写。
- 关键词选择“主题词 + 关键技术词”，删除中文关键词中的英文混入。

**评审原话示例**
- “中英文摘要是空白的。”
- “摘要过于简单，建议扩充到300字左右，增加摘要的基本要素。”

### 4) 需求分析与系统设计章节边界混乱

**常见表现**
- 需求分析缺图（业务流程图、用例图、数据流图/数据字典）。
- 把设计内容写进需求章，或需求章只列功能点。
- 缺“国内外研究现状”等绪论关键内容。

**修改动作**
- 需求章只回答“要做什么、为什么做”；
- 设计章回答“怎么设计”；
- 实现章回答“怎么实现与验证”。
- 系统设计章节补充整体功能模块图（HIPO图），体现功能分层结构。

**评审原话示例**
- “缺少需求分析。需要增加一章。”
- “把第三章分成两章：需求分析和系统设计。”
- “系统设计部分：增加整体功能模块图（HIPO）”

### 5) 数据库设计步骤不完整或表达不规范

**常见表现**
- 只有库表，没有“概念 -> 逻辑 -> 物理”过程。
- ER 图不规范、关系标注错误或不可读。
- 关系模式主键/实体命名表达不清。

**修改动作**
- 必须补齐三步：概念结构（ER）-> 逻辑结构（关系模式）-> 物理结构（表结构、约束、索引）。
- 统一图形规范与命名规范。
- 关系模式中明确主键（按要求用下划线标识）。

**评审原话示例**
- “数据库设计缺少步骤。不能直接给出数据库表。”
- “E-R 图不规范。”

### 6) 图表可读性与规范性差

**常见表现**
- 图名/图号错误，图和正文未形成引用关系。
- 图表内容错误、布局松散、分辨率低、无法阅读。
- 表格跨页无表头。

**修改动作**
- 统一“图号+图名+正文引用”。
- 全文图表做一次“正确性 + 清晰度 + 可打印性”巡检。

**评审原话示例**
- “有些图片有错误，有些不能阅读。”
- “检查全文的图，要保证内容正确，美观并能阅读。”

### 7) 实现与测试证据不足

**常见表现**
- 实现章节只有文字原则，没有模块实现细节。
- 缺程序流程图、缺运行截图、缺测试结果截图。
- 截图不能证明独立完成（无系统标识/开发者标识）。

**修改动作**
- 每个核心模块按固定结构写：功能说明 -> 运行界面 -> 处理流程图/时序图 -> 关键代码与分析。
- 测试章节提供可复核证据（测试用例、结果、截图）。

**评审原话示例**
- “你的论文算法流程图完全缺失。”
- “测试部分没有截屏图，应增加相关测试图片验证设计的有效。”

### 8) 附录与过程材料不完整

**常见表现**
- 缺附录或源代码附录不足。
- 源代码用截图而非文本展示。
- 任务书内容与正文映射不完整。

**修改动作**
- 附录放“主要源代码文本 + 关键中间材料”。
- 对照任务书逐项建立“任务项 -> 论文章节/证据页码”映射。

**评审原话示例**
- “缺附录。”
- “缺少附录。”
- “把你开发的主要程序代码附录到论文后。”

### 9) 学术写作方式偏“说明书化”

**常见表现**
- 只列功能和界面，缺分析推导与设计依据。
- 章节主次不分，核心章节篇幅不足。
- 语言偏口语或技术报告风格，不够学术化。

**修改动作**
- 每章增加“为什么这样设计”的依据与取舍。
- 提高核心章节（需求/设计/实现/测试）论证深度和篇幅占比。

**评审原话示例**
- “论文不能写成软件开发设计文档。”
- “不能仅仅是部分工作的罗列。”

### 10) 题目命名不规范（高频）

**常见表现**
- 题目过于通用，缺少项目独特标识。
- 题目语义不完整或存在语法问题。
- 题目过长，信息堆叠，表达不聚焦。

**修改动作**
- 题目遵循“单位/场景标识 + 项目名称 + 设计与实现”这一规范思路。
- 确保题目能体现独立工作对象，同时避免通用化命名。
- 保持语法正确与长度适中。

**评审原话示例**
- “论文题目：必须有项目名，不能是通用系统。”
- “题目不完整，建议改成：基于 springboot 的电商秒杀系统的设计与实现”

## 三、最终自查表（可直接打勾）

> 建议按顺序检查：先“硬性格式”，再“结构内容”，最后“证据闭环”。

- [ ] 任务书不空白，且任务项在正文中均有对应章节与证据。
- [ ] 诚信声明已手写签名并嵌入文档。
- [ ] 每章另起一页，页眉页码与学校模板一致。
- [ ] 摘要完整（中英文），关键词聚焦且规范。
- [ ] 绪论包含选题背景、国内外研究现状、目标与章节安排。
- [ ] 需求分析包含业务流程图、用例图（必要时补数据流图/数据字典）。
- [ ] 系统设计包含整体功能模块图（HIPO图），体现功能分层。
- [ ] 数据库设计完整呈现“概念ER -> 逻辑关系模式 -> 物理表结构”。
- [ ] 关系模式中主键标识正确（按要求下划线标识）。
- [ ] 中文关键词不混入英文词；英文关键词放在英文摘要部分。
- [ ] 论文题目规范：有项目标识、语义完整、不过长，避免通用题目。
- [ ] 图表可读、编号正确、在正文有引用，跨页表有表头。
- [ ] 实现章包含模块流程图/时序图、运行截图、关键代码分析。
- [ ] 测试章有测试用例、执行结果、截图和结论，不是概述性描述。
- [ ] 附录包含主要源代码（文本形式，非截图）与必要中间材料。
- [ ] 参考文献数量达标（建议 15 左右），正文标注与文后条目一一对应。

## 四、建议你的修订顺序（高效率版）

1. **先修硬门槛**：格式、签名、封面、页眉页码、章节分页。  
2. **再补结构短板**：绪论现状、需求分析图、数据库三步设计。  
3. **最后补证据闭环**：实现截图、测试截图、附录源码、参考文献标注。

这样做可以最快把“不能通过”的高风险问题先清零，再提升内容质量。
