# 第四章 系统概要设计

## 4.1 系统架构设计

### 4.1.1 总体架构

本系统采用前后端分离的 B/S 架构，由前端层、应用服务层和数据层三层组成。

**【请插入图片：图4-1 系统总体架构图 — 系统架构分层示意图】**

- **前端层**：负责用户交互和数据展示。C 端面向老年人及家属，支持 PWA 特性；B 端面向工作人员和管理人员，提供管理后台功能。
- **应用服务层**：负责业务逻辑处理和接口服务。采用 Go + Gin 框架构建 RESTful API，处理需求提交、地理围栏匹配、任务管理等核心业务。
- **数据层**：负责数据存储和管理。采用 MySQL 存储业务数据，Redis 缓存热点数据和会话信息。

### 4.1.2 技术架构选型

**后端技术栈**：

| 组件 | 技术 | 选型理由 |
|------|------|----------|
| 编程语言 | Go 1.25 | 原生支持高并发，编译型语言性能优异，部署简单 |
| Web框架 | Gin | 轻量级高性能，中间件机制灵活，API友好 |
| ORM | GORM | 功能完善，支持代码优先模式，自动迁移 |
| 数据库 | MySQL 8.0 | 开源免费，社区成熟，utf8mb4支持emoji |
| 缓存 | Redis 7.0 | 高性能内存数据库，支持多种数据结构 |
| 认证 | JWT | 无状态认证，适合分布式架构 |

**前端技术栈**：

| 组件 | 技术 | 选型理由 |
|------|------|----------|
| 框架 | Vue 3 + TypeScript | 响应式框架，类型安全，生态完善 |
| 状态管理 | Pinia | Vue 3官方推荐，简洁直观 |
| UI组件库 | Element Plus | 企业级组件库，开箱即用 |
| 离线支持 | PWA (vite-plugin-pwa) | 支持离线访问，可安装到桌面 |

### 4.1.3 部署架构

**【请插入图片：图4-2 系统部署架构图 — 部署架构示意图】**

系统采用 Docker 容器化部署，通过 Nginx 作为反向代理，将请求分发到前端静态资源和后端 API 服务。MySQL 和 Redis 使用独立容器部署，便于扩展和管理。

## 4.2 功能模块设计

### 4.2.1 后端模块结构

后端采用分层架构，按照职责划分为 Handler、Service、Repository 三层。

**【请插入图片：图4-3 后端模块结构图 — 后端分层架构图】**

**分层职责说明**：

| 层次 | 职责 | 示例 |
|------|------|------|
| Handler | 参数校验、响应格式化 | 解析请求参数、调用Service、返回JSON |
| Service | 业务逻辑、事务控制 | 围栏匹配、状态流转、通知触发 |
| Repository | 数据库操作、查询封装 | CRUD操作、复杂查询 |

**C端（用户端）结构**：

主要模块包括：快速开通、需求提交、需求列表、需求详情、服务评价等。

**B端（管理门户）结构**：

**【请插入图片：图4-5 B端模块结构图 — B端功能模块结构】**

主要模块包括：登录认证、工作台首页、任务管理、站点管理、围栏管理、用户管理、权限管理、统计报表等。

### 4.2.3 核心业务模块设计

**（1）地理围栏分发模块**

**【请插入图片：图4-6 地理围栏匹配流程图 — 围栏匹配算法流程】**

系统接收到需求提交请求后，自动获取用户坐标，调用地理围栏引擎进行站点匹配。匹配成功后将需求分配到对应站点任务池，并触发通知服务。

**（2）任务状态流转模块**

**【请插入图片：图4-7 任务状态流转图 — 任务状态机示意图】**

任务状态包括：pending（待分发）、dispatched（已分发）、claimed（已认领）、processing（处理中）、completed（已完成）、cancelled（已取消）。状态流转遵循业务规则，确保任务处理的正确性。

**（3）通知触发模块**

系统在以下业务节点自动触发通知：需求创建、任务认领、任务完成、任务转派等。通知通过站内信和邮件两种渠道发送，确保信息及时触达。

## 4.5 安全性设计

### 4.5.1 认证与授权

**（1）双端认证**

系统支持B端和C端独立认证：
- B端：手机号 + 密码登录
- C端：支持短信验证码登录和密码登录两种方式
- Token中type字段区分端类型（b_end / c_end），防止跨端访问

**（2）Token黑名单**

用户登出时，Token加入Redis黑名单，实现即时失效。

**（3）RBAC权限控制**

采用自定义三表RBAC模型：
- permissions表：定义权限
- roles表：定义角色
- role_permissions表：关联角色和权限

权限检查流程：
1. 解析Token获取用户身份
2. 查询用户的角色和权限列表
3. 检查是否拥有所需权限
4. Admin角色跳过所有权限检查

### 4.5.2 数据安全

**（1）密码存储**

使用bcrypt算法加密存储密码。

**（2）敏感数据脱敏**

API响应中对手机号等敏感信息进行脱敏处理。

### 4.5.3 接口安全

**（1）请求限流**

通过中间件实现API请求频率限制，防止恶意请求。

**（2）参数校验**

Handler层对请求参数进行严格校验，防止非法数据注入。
