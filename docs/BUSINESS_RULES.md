# 业务规则 (Business Rules)

## 1. 认证与服务申请 (Authentication & Service Request)

### 1.1 未登录用户快速申请规则 (Quick Start Logic)
当未登录用户提交服务申请时，系统采用 **后端自动注册 (Backend-led Registration)** 策略，而非前端分步注册。

**逻辑流程：**
1.  **前端行为**：
    前端收集用户手机号、验证码、姓名、地址及服务需求详情，打包调用单一接口 `/c/auth/quick-start`。

2.  **后端行为** (原子事务)：
    *   **验证身份**：校验短信验证码合法性。
    *   **账号检查**：
        *   若手机号未注册：自动创建新用户账号（初始状态 active）及客户档案 (Customer Profile)。
        *   若手机号已注册：更新现有用户的姓名（如果提供了新姓名）。
    *   **创建需求**：创建对应的服务请求单 (Service Request)。
    *   **自动登录**：生成并返回 JWT Token（Access Token + Refresh Token）。

**设计考量：**
*   **低门槛**：消除老年用户的注册认知负担，实现“填单即用”。
*   **数据一致性**：注册与提单在同一数据库事务中，避免中间状态。

## 2. 昵称显示规则 (Nickname Display Rules)

### 2.1 个人中心显示
*   **已登录状态**：
    *   优先显示用户设置的真实姓名（如“张大爷”）。
    *   若未设置姓名，显示“未设置昵称”。
    *   手机号需进行脱敏处理（中间四位隐藏，如 `138****0008`）。
*   **未登录状态**：
    *   显示“点击登录”。
