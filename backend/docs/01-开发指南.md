# sCare 开发环境启动指南

## 1. 本地依赖

本地开发建议准备以下运行时：

| 组件 | 建议版本 | 用途 |
|------|----------|------|
| Go | 1.25+ | 后端服务、测试、命令行工具 |
| Node.js | 18+ | 前端开发与构建 |
| Docker / Docker Compose | 最新稳定版 | 启动 MySQL / Redis |

默认端口如下：

| 服务 | 端口 | 说明 |
|------|------|------|
| 后端 API | `8080` | Gin 服务、Swagger、静态文件 |
| MySQL | `3306` | 由 `backend/docker-compose.yml` 启动 |
| Redis | `6379` | 由 `backend/docker-compose.yml` 启动 |
| 管理门户 | `3001` | Vite dev server |
| C端 | `5174` | Vite dev server，HTTPS |

推荐启动顺序：

1. 启动 MySQL / Redis。
2. 启动后端 `go run . serve` 或 `air -c .air.toml`。
3. 启动管理门户和 C 端前端。

## 2. 配置文件说明

### 2.1 后端配置：`backend/.env`

首次使用请复制：

```bash
cd backend
cp .env.example .env
```

关键配置项：

| 配置项 | 是否必须 | 本地默认值 | 说明 |
|--------|----------|------------|------|
| `SERVER_PORT` | 否 | `8080` | 后端服务端口 |
| `SERVER_MODE` | 否 | `debug` | `debug / release / test` |
| `DB_HOST` / `DB_PORT` / `DB_USER` / `DB_PASSWORD` / `DB_NAME` | 必须 | 与 Compose 默认一致 | MySQL 连接信息 |
| `REDIS_HOST` / `REDIS_PORT` / `REDIS_PASSWORD` | 必须 | 与 Compose 默认一致 | Redis 连接信息 |
| `JWT_SECRET` | 必须 | 示例值 | JWT 签名密钥，生产环境必须替换 |
| `SECURITY_ID_CARD_ENCRYPT_KEY` | 必须 | 示例值 | 身份证等敏感数据加密 Key，需为合法 base64 |
| `AMAP_KEY` | 推荐 | 空 | 地址解析、地图相关能力需要 |
| `STORAGE_DRIVER` | 否 | `local` | 本地开发默认本地文件存储 |
| `SMTP_*` | 否 | 空 | 邮件通知，不配置也可启动 |

生成本地加密 Key：

```bash
openssl rand -base64 32
```

### 2.2 管理门户配置：`frontend/management-portal/.env`

首次使用请复制：

```bash
cd frontend/management-portal
cp .env.development.example .env
```

关键配置项：

| 配置项 | 是否必须 | 默认值 | 说明 |
|--------|----------|--------|------|
| `VITE_API_BASE_URL` | 必须 | `http://localhost:8080/api/v1` | 管理门户后端接口地址 |
| `VITE_APP_TITLE` | 否 | `sCare 管理后台` | 页面标题 |
| `VITE_AMAP_KEY` | 推荐 | 空 | 站点地图、围栏编辑需要 |
| `VITE_AMAP_SECURITY_JS_CODE` | 推荐 | 空 | 高德地图安全密钥 |
| `VITE_C_END_BASE_URL` | 推荐 | `https://localhost:5174` | 站点二维码跳转到 C 端时使用 |

### 2.3 C端配置

C端本地开发默认不依赖额外 `.env` 文件：

- 接口通过 Vite 代理转发到 `http://localhost:8080`
- 开发服务器默认地址为 `https://localhost:5174`
- 可选环境变量 `VITE_MOCK_USER=true` 用于本地调试 Mock 用户逻辑

## 3. 启动 MySQL / Redis 并初始化数据库

在 `backend` 目录执行：

```bash
cd backend
cp .env.example .env
docker compose up -d
```

常用检查命令：

```bash
docker compose ps
docker compose logs -f mysql
docker compose logs -f redis
```

### 3.1 数据库初始化行为

MySQL 首次启动时会自动执行：

4. `database/seeds/003_seed_stations.sql`
5. `database/seeds/004_seed_requests.sql`
6. `database/seeds/005_seed_notifications.sql`
7. `database/seeds/006_seed_news.sql`
8. `database/seeds/007_seed_menus.sql`

当前 fresh init 后的默认数据规模：

- 用户：`12`
- 服务站点：`4`
- 服务围栏：`6`

说明：

- `users.password_hash` 允许为 `NULL`，用于 C 端快速开通后未设置密码的用户

```bash

```

### 3.2 手动验证数据库

```bash
docker exec -it scare_mysql mysql -uscare_user -pscare_pass scare_db
```

可执行的核验 SQL：

```sql
SHOW TABLES;
SELECT COUNT(*) FROM users;
SELECT COUNT(*) FROM service_stations;
SELECT COUNT(*) FROM service_zones;

SHOW COLUMNS FROM users LIKE 'password_hash';
```

### 3.3 迁移记录修复说明

在历史开发过程中，可能出现“表结构已经变更成功，但 `schema_migrations` 记录缺失”的情况。典型现象是：

- `go run . migrate` 在较早 SQL 迁移上报 `Duplicate column name`
- 实际表结构已经包含对应字段，例如：
  - `service_requests.service_location_lat/service_location_lng/source_station_id/dispatch_basis/needs_manual_verify`
  - `users.password_hash` 已允许为 `NULL`

处理原则：

1. 先检查目标 SQL 的效果是否已经体现在数据库表结构中
2. 如果结构已生效，不要重复执行 SQL 本体
3. 只补齐 `schema_migrations` 中缺失的迁移记录
4. 再重新执行 `go run . migrate`，确认输出为“执行: 0，跳过: N”

本地排查常用命令：

```bash
cd backend

# 查看已登记迁移
docker exec scare_mysql mysql -uroot -pscare_root_pass scare_db \
  -e "SELECT filename, applied_at FROM schema_migrations ORDER BY filename;"

# 查看关键表结构
docker exec scare_mysql mysql -uroot -pscare_root_pass scare_db \
  -e "SHOW COLUMNS FROM service_requests; SHOW COLUMNS FROM users;"
```

注意：

- 迁移记录修复只适用于“结构已生效但记录缺失”的场景
- 若结构未生效，应优先修正迁移 SQL 的幂等性或按正常迁移流程执行
- 本项目当前已确认需要保持一致的迁移包括：
  - `add_request_dispatch_fields.sql`
  - `allow_nullable_user_password_hash.sql`
  - `grant_staff_task_pool_and_restore_family_fixture.sql`

## 4. 启动后端服务

标准启动：

```bash
cd backend
go mod download
go run . serve
```

可选参数：

```bash
go run . serve --port 8081
go run . serve --mode release
go run . serve --config .env
```

若本机已安装 `air`，也可以使用热重载：

```bash
cd backend
air -c .air.toml
```

启动成功后可访问：

- 健康检查：`http://localhost:8080/api/v1/health`
- Swagger：`http://localhost:8080/swagger/index.html`
- 静态文件：`http://localhost:8080/static/...`

## 5. 启动前端

### 5.1 管理门户

```bash

cp .env.development.example .env

npm run dev
```

### 5.2 C端

```bash
cd frontend/c-end

npm run dev
```

访问地址：`https://localhost:5174`

- C端使用 `@vitejs/plugin-basic-ssl`，浏览器首次访问会提示本地证书风险
- 这是开发环境行为，接受本地证书后即可正常访问

## 9. 常见问题

### Q1: `go run . serve` 启动时下载依赖失败

首次运行需要能够访问 Go 模块源；先执行：

```bash
cd backend
go mod download
```

### Q2: Docker 服务已启动，但数据库没有种子数据

请直接执行 fresh init：

```bash
cd backend
docker compose down -v
docker compose up -d
```

### Q3: C端打不开或浏览器提示证书风险

C端开发服务器默认使用 HTTPS，本地证书提示是预期行为。浏览器接受本地证书后即可访问 `https://localhost:5174`。

### Q4: 地图选点、围栏编辑页面无法使用

请检查以下配置：

- 后端 `AMAP_KEY`
- 管理门户 `VITE_AMAP_KEY`
- 管理门户 `VITE_AMAP_SECURITY_JS_CODE`

### Q5: 接口返回 401 或登录失败

优先检查：

1. 后端是否已启动在 `8080`
2. MySQL / Redis 是否 `healthy`
3. 测试账号是否来自 fresh init 的种子数据
