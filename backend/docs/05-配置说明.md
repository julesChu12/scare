**版本**：v1.0
**日期**：2026年1月16日

## 1. 配置文件结构

项目使用 Viper 读取配置，默认配置文件路径为 `configs/config.yaml`。
支持通过环境变量覆盖配置，环境变量前缀为 `SCARE_`。

### 1.1 `configs/config.yaml` 示例

```yaml
server:
  port: 8080                # 服务监听端口
  mode: debug               # 运行模式: debug, release, test
  name: "scare-backend"

database:
  host: "127.0.0.1"
  port: 3306
  user: "root"
  password: "password"      # 生产环境请使用环境变量覆盖
  dbname: "elderly_care"
  charset: "utf8mb4"
  max_idle_conns: 10
  max_open_conns: 100

redis:
  host: "127.0.0.1"
  port: 6379
  password: ""              # 生产环境请使用环境变量覆盖
  db: 0
  pool_size: 100

jwt:
  secret: "your-256-bit-secret" # 必须修改！
  expires_in: 24            # Token有效期(小时)
  refresh_expires_in: 168   # Refresh Token有效期(小时)

log:
  level: "debug"            # debug, info, warn, error
  filename: "app.log"
  max_size: 10              # MB
  max_backups: 5
  max_age: 30               # Days

```

## 2. 环境变量映射

为安全起见，生产环境建议通过环境变量注入敏感信息。

| 配置项 | 环境变量 | 说明 |
|-------|----------|------|
| database.password | `SCARE_DATABASE_PASSWORD` | 数据库密码 |
| redis.password | `SCARE_REDIS_PASSWORD` | Redis 密码 |
| jwt.secret | `SCARE_JWT_SECRET` | JWT 签名密钥 |
| server.mode | `SCARE_SERVER_MODE` | 运行模式 (生产环境设为 release) |

---

## 3. 核心配置说明

### 3.1 运行模式 (`server.mode`)
*   `debug`: 开启详细日志，Gin 输出请求详情，Swagger 接口文档可用。
*   `release`: 关闭调试输出，性能更优，Swagger 接口默认关闭（需手动配置开启）。

### 3.2 数据库 (`database`)
*   项目启动时会自动检查数据库连接。
*   **Code First**: 启动时会自动执行 `db.AutoMigrate()` 同步表结构。

### 3.3 JWT (`jwt`)
*   `secret`: 用于签名 Token，泄露会导致安全风险。生产环境请务必使用强随机字符串。

---

## 4. 权限配置（自定义 RBAC）

权限通过数据库三表（`permissions`、`roles`、`role_permissions`）管理，无需额外配置文件。

*   权限数据在 `database/seeds/seed.sql` 中初始化。
*   运行时通过 `PermissionService` 从数据库加载。
