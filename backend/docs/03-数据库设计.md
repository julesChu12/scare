# 数据库设计

**版本**：v1.1 (Code First 修订版)
**日期**：2026年1月16日
**设计模式**：Code First (以 Go 结构体为准，本主要作为设计参考)

---

## 1. 设计规范变更说明

1.  **Code First**: 数据库表结构由 Go 代码中的 GORM 模型自动迁移生成 (`AutoMigrate`)。
2.  **禁用 ENUM**: 数据库层面不使用 `ENUM` 类型，统一使用 `VARCHAR` 存储状态码，在 Go 代码应用层维护常量定义和校验。
3.  **禁用空间类型**: 不使用 MySQL 的 `POLYGON` 或 `GEOMETRY` 类型。
    *   **坐标点**: 使用 `latitude` 和 `longitude` (DECIMAL) 两个字段存储。
    *   **多边形围栏**: 使用 `JSON` 字段存储坐标点数组 `[{lat, lng}, ...]`。
    *   **围栏匹配**: 采用 **应用层内存匹配** 策略（启动时加载所有围栏到内存 R-Tree 或列表，使用射线法计算）。

## 4. 索引策略调整

由于移除了 MySQL 空间扩展，地理位置相关的查询策略变更如下：

1.  **围栏匹配 (Point in Polygon)**:
    *   **数据库**: 不做匹配。
    *   **应用层**: 系统启动或围栏更新时，将 `service_zones` 全量加载到 Go 内存中（构建 R-Tree 索引或简单列表）。
    *   **计算**: 每次需求提交时，在内存中遍历围栏进行 `PointInPolygon` 计算。

2.  **附近查询 (Radius Search)**:
    *   如果需要查询"附近的站点"，使用简单的矩形边框 (Bounding Box) SQL 查询：
        ```sql
        WHERE latitude BETWEEN ? AND ? AND longitude BETWEEN ? AND ?
        ```
    *   然后在内存中精细计算距离。
